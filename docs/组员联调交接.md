# CookCoach · 导师客户端交接

打开 `unity/Assets/Scenes/KitchenTutorPractice.unity`，点 Play。厨房沿用丁书萱提供的现代厨房。郭冀康现负责场景道具与导师客户端。默认使用桌面鼠标和本地练习规则，等待团队流程与真实模型接入。

## 已交付的厨房道具

`Assets/CookCoachTutor/Workbench/PrepStation.prefab` 包含砧板、刀、番茄、蛋碗、上菜盘和各阶段食材。炉灶、旋钮和锅沿用整合场景内原有物体。WASD 或方向键走动，按住鼠标右键环视，F 回到灶台。先点刀，再分三次点番茄；按住蛋碗边缘，用鼠标连续绕一圈。两项备料可交换顺序。点炉灶旋钮开火，先把台面右侧的黑色橄榄油瓶拖到锅上，再将蛋碗拖到锅上松手，再拖番茄块入锅，随后将右侧盘中的熟蛋拖回锅中。这时可以把油瓶旁的白色盐罐拖到锅上撒盐，再按住锅内绕圈合炒，点旋钮关火，再把锅拖向空盘装盘。熟蛋回锅也可先点熟蛋、再点锅。提前装盘会提示原因，并在本轮记录中记为一次受阻。拖错可松手重来，Esc 可取消拖动。 厨房内部使用基于家具和墙面烘出的可行走网格。改动厨房布局时请同步更新 KitchenFloor 和工位定位。点击导师卡和记录面板不会触发背后的道具。轻点蛋碗或锅不会完成搅打或倒蛋；取消手势和拖错目标均不会提交成功动作。需要重新练习时，从右上角“交互记录”选择“重新开始本轮”。

| 物体编号 | 交给流程的操作 | 场景中的可见结果 |
|---|---|---|
| tomato | cut_tomato | 番茄切块 |
| egg_bowl | beat_egg | 碗中出现蛋液 |
| stove_switch | turn_on_stove | 开关与火焰亮起 |
| pan | fry_egg / fry_tomato | 鸡蛋盛出、番茄入锅 |
| plate | finish_dish | 合炒、关火、装盘 |

每次收到已受理的快照，客户端通过 `KitchenTutor.ContextChanged` 刷新模型。首次处于未开火状态时点锅会提交 `fry_egg`，锅和碗保持原貌。关掉当前六步场景时注销这组定位点。独立热锅小样使用自己的旋钮定位点。

## 给朱玉 · 状态与操作结果

请给场景的 `Stove practice → Workflow` 拖入实现 `IKitchenWorkflow` 的 MonoBehaviour。接口位于 `Runtime/KitchenWorkbench.cs`。字段为空时走本地规则，日志使用 `desktop_objects_local_rules`。指定正式组件后走你的规则，日志使用 `kitchen`。请交组件名、主工程场景路径、测试版本，以及你在 Unity 2022.3.62f1 上运行的结果。

- 界面开始或重置时调用你的 `BeginLesson(KitchenTutor tutor)`。请生成新会话，并通过 `tutor.SetContext(initial)` 发布初始状态。
- 玩家点道具时调用你的 `Attempt(string actionId, string targetId, KitchenTutor tutor)`。请在本次调用中发布结果，或在自行实现的异步流程中处理输入去重。请使用 `tutor.ReportAction(nextContext, ev)`，食材、火焰、进度和回顾依据同一份快照刷新。
- 请先过两条路径：先打蛋再切番茄仍能通关；备好料、未开火时点锅会受阻。再测一次请求等待时重开，旧轮回复不会影响新轮。

| 阶段 | 操作 | 本项目教学条件 |
|---|---|---|
| S1 / S2 | cut_tomato / beat_egg | 备料可交换顺序 |
| S3 | turn_on_stove | S1、S2 已完成 |
| S4 | fry_egg | 已开火并加入油，蛋已打散；炒好盛出 |
| S5 | fry_tomato | 鸡蛋已盛出且炉灶开启 |
| S6 | return_cooked_egg → stir_fry → turn_off_stove → finish_dish | 熟蛋回锅 → 锅中合炒 → 手动关火 → 装盘 |

菜谱版本 `2` 仍为六个主阶段。油瓶 `oil_bottle` 发出 `add_oil`，仅在开启炉火后、倒入蛋液前有效；缺油尝试炒蛋返回 `oil_missing`。盐罐 `salt_shaker` 发出 `add_salt`，仅在熟蛋回锅后、合炒动作完成前可选用一次。两项均在快照中记录布尔值 `oil_added` 和 `salt_added`。重新开始时都为 false，重复操作受阻，进度仍以 Unity 的判定为准。

S6 的 `snapshot.finish_phase` 是等待执行的动作编号。四次调用的目标依次为 `pan`、`pan`、`stove_switch`、`plate`，每次成功均发布新版本。关火成功时立即写入 `stove_on=false`，装盘成功才把 S6 加入完成列表。

1. 每次开始或重置时生成新的 `session_id`，调用 `SetContext(initial)`。正式来源使用默认 `InputSource="kitchen"`。
2. 有结果的操作统一调用一次 `ReportAction(nextContext, ev)`。**同一版本直接调用这个方法即可**。事件含 `action_id, target_id, outcome, reason`，成功用 `ok`，受阻用 `blocked`。每个受理的尝试递增 `state_version`，即使食材未变化。重复通知同一版本会被忽略。只同步状态时使用 `SetContext`。
3. `nextContext` 附最新快照和最近操作，包含本次尝试。`step_count=6`，`completed_steps` 按实际完成填写，`current_step` 为下一阶段。结束时传 `current_step="done"`、全部六个完成编号和 `stove_on=false`，回顾会自动展开。
4. 每个道具的输入入口在提交动作前检查 `tutor.IsWaiting`，或订阅 `WaitingChanged` 禁用输入。等待时允许取消和重置。错误尝试由 `ReportAction` 自动求助，无需再发一次请求。

验收用例：交换备料顺序；关火时炒蛋被阻止且蛋液留在碗中；点击旋钮后清除高亮；新一轮隔离旧回复。请交正式工程入口、桌面操作方式和运行结果。

## 给魏伊林 · 指导接口

拟对齐的本地地址为 `POST /api/v1/guidance`，健康检查为 `GET /health`。将 KitchenTutor 的 Mode 设为 Http，Endpoint 指向实际服务。请求为 UTF-8 JSON；密钥只在后端配置。示例见 `shared/guidance.request.example.json` 与 `shared/guidance.response.example.json`。

- 原样回传 `request_id, session_id, state_version`。请求带菜谱版本、当前快照、最近 10 个操作以内、最近 6 条对话以内，以及本次已注册的可用物体编号。
- `trigger` 使用 `error / hint / question`。`guidance.message` 为非空文本，`hint_level` 目前接受 `check / explain / direct`，`highlight_target_id` 可留空。需要定位时从该请求的 `allowed_highlight_targets` 选一个有效编号。
- `source` 当前接受 `llm / fallback / mock`。请为真实调用返回 llm，为备用文本返回 fallback。客户端超时为 20 秒，失败后允许手动重试。
- 请保留同一请求编号对应的实际模型输入、原始输出、校验结果与耗时。客户端 JSON 保存的是发往 API 的载荷和收到的指导，两份记录通过编号关联。
- 请提供两段真实轨迹：首次出错得到提示；追问“开关在哪里”时模型结合历史请求高亮，开火后再问能给出更新后的回答。

## 一起验收

先让朱玉的流程驱动导师，再把魏伊林的服务接入同一个入口。按“打蛋 → 切番茄 → 未开火尝试炒蛋 → 追问开关位置 → 开火 → 完成菜谱”录一轮。郭冀康在交互记录面板查看请求与回复、导出本轮 JSON，和魏伊林核对相同请求编号。最终报告分别标出厨房输入来源、回复来源、实际执行结果及测试版本。
